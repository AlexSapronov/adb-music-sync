# ADB Music Sync

Надёжный перенос больших музыкальных библиотек с Windows PC на Android-устройства через ADB.

![CI](https://github.com/AlexSapronov/adb-music-sync/actions/workflows/ci.yml/badge.svg)

## Назначение

Windows MTP / Проводник нестабильны при копировании больших медиатек: зависают, падают, теряют файлы посреди переноса. **ADB Music Sync** передаёт музыку через `adb` по одному файлу, корректно переживая временные ошибки соединения и отключение устройства, с проверкой уже существующих файлов и явным выбором хранилища (внутренняя память / SD-карта).

## Возможности (MVP)

- Автообнаружение Android-устройства по USB (ADB).
- Определение внутренней памяти и съёмных SD-карт (не привязано к конкретному пути).
- Явный выбор хранилища и папки назначения.
- Рекурсивное сканирование локальной библиотеки с сохранением структуры.
- Предварительная проверка: какие файлы уже на устройстве (по размеру), что нужно передать, объём, свободное место.
- Передача по одному файлу через временное имя `.part` (незавершённый файл не виден плееру).
- Обработка отключения устройства / исчезновения SD-карты: очередь останавливается, состояние сохраняется, продолжение возможно.
- Повтор неудачных файлов (`Повторить ошибки`).
- Корректная работа с кириллицей, пробелами, скобками, апострофами, `&`, `#`, Unicode, японскими символами.

## Каталог музыки для ChatGPT и Poweramp

1. Подключите плеер, выберите устройство и хранилище (например SD-карту).
2. В «Папка назначения» укажите папку **на устройстве**, где уже лежит музыка, например `Music`. Папка музыки на ПК для экспорта не нужна.
3. Нажмите **«Экспорт каталога для плейлистов…»** и сохраните `jm21_catalog.json` на ПК.
4. Пришлите JSON в ChatGPT и попросите составить тематические M3U8-плейлисты.
5. Поместите готовые плейлисты в подпапку `ChatGPT_Playlists` выбранной папки музыки. Для JM21 это обычно `/storage/external_sd/Music/ChatGPT_Playlists`. Пересканируйте библиотеку/плейлисты в Poweramp; папка музыки должна быть включена в его библиотеку.

JSON в UTF-8 содержит точный абсолютный путь (`path`), путь от папки музыки (`relative_path`), **готовый путь от папки плейлистов (`playlist_path`)**, имя файла, папки и расширение. Например, `Artist/Album/01 Song.flac` получит `playlist_path: ../Artist/Album/01 Song.flac`. Поля `music_root` и `playlist_directory` явно указывают расположение на Android, а `schema_version` позволяет читать формат программно.

Экспорт рекурсивно читает реальные файлы, отбирает поддерживаемые приложением аудиоформаты, исключает обложки, M3U и незавершённые `.part`. Используются существующий AdbClient и текущий transport ID устройства. Музыка не скачивается и не изменяется. Чтение выполняется в фоне; ошибка сканирования не заменяет ранее сохранённый каталог. Пустая папка даёт каталог с нулём треков, несуществующая/недоступная — ошибку.

**Ограничение:** это каталог файлов, не выгрузка аудиотегов: исполнителя, жанр и настроение можно определить по названиям и структуре папок, но теги и длительность пока не извлекаются. Имена с переводами строк сохраняются в JSON, однако помечаются `m3u_compatible: false`, поскольку построчный M3U8 не может их представить.

## Поиск полных дубликатов (0.2.0)

Во вкладке **«Дубликаты»** можно найти и убрать лишние копии на выбранном устройстве. Укажите папку музыки в поле «Папка назначения» над вкладками (обычно `Music`). Локальная папка ПК не нужна.

1. Нажмите **«Найти дубликаты»**. Приложение сначала сравнивает размеры; SHA-256 вычисляется на Android только для файлов с совпадающими размерами. Музыка не скачивается.
2. Проверьте группы, снимите флажки с тех, которые хотите сохранить целиком, и выберите в каждой группе **одну копию для сохранения**. Остальные пути показаны под группой.
3. Закройте Poweramp и нажмите **«Переместить выбранные в карантин»**. Хеши повторно проверяются. Лишние файлы перемещаются в `.adb-music-sync-quarantine/<ID>/files/` в корне выбранного хранилища. Файловые M3U/M3U8 в папке музыки получают ссылки на оставшиеся копии; исходное содержимое сохраняется в журнале операции.
4. Пересканируйте библиотеку и плейлисты Poweramp. Карантин должен быть исключён из его музыкальных папок (рекомендуется индексировать только `Music`).
5. При необходимости нажмите **«Обновить карантин»**, выберите операцию и **«Восстановить»**. Журнал хранится на устройстве, поэтому восстановление доступно после перезапуска и отключения USB. Прерванные операции тоже появятся в списке.
6. Чтобы **реально освободить место**, выберите завершённую операцию и **«Удалить из карантина навсегда»**. Это необратимо и требует отдельного подтверждения в приложении. Перед удалением снова проверяются оставшиеся копии. Прерванное окончательное удаление можно продолжить, но уже нельзя отменить.

Карантин сам по себе **не освобождает место**: файл перемещается внутри того же хранилища. Журнал с резервными копиями плейлистов сохраняется даже после окончательного удаления; пустые каталоги карантина могут остаться.

**Пределы и защита:** сравниваются именно байты файла. Одна песня в разных форматах, с разными тегами или разной мастеринг-версией не считается дублем. Поддерживаются те же аудиоформаты, что при переносе. Обновляются только файловые `.m3u`/`.m3u8` **внутри выбранной папки**, в UTF-8 (с BOM или без) и UTF-16; внутренние плейлисты базы Poweramp и плейлисты за пределами папки не изменяются. Плейлист в неизвестной кодировке блокирует очистку до его конвертации. Имена с переводами строк не очищаются. Очистка корня хранилища запрещена: выберите отдельную папку музыки.

Восстановление не перезаписывает занятые исходные пути или плейлисты, изменённые после очистки: при конфликте операция останавливается с сообщением. Если выполняли несколько очисток с пересекающимися файлами/плейлистами, восстанавливайте их от последней к первой. Во время операций не перемещайте музыку вручную и не редактируйте плейлисты. Кнопка «Остановить» действует между файлами; текущий SHA-256 может занять время. Перенос, экспорт и работа с дублями выполняются последовательно. После операций с файлами прежний план переноса сбрасывается — перед новой передачей нажмите «Проверить».

На Android необходимы штатные команды `find`, `stat`, `sha256sum`, `base64`, `readlink`, `mv -n` (Android toybox). Ошибка команды или обрыв связи останавливает операцию; незавершённый журнал остаётся доступен для восстановления.

## Почему ADB вместо MTP

MTP-драйвер Windows — известный источник сбоев при больших объёмах. ADB (`adb push`) стабилен, даёт точный контроль над каждым файлом, позволяет проверять наличие файла до передачи и не трактует середину прерванной копии как готовый файл.

## Системные требования

- Windows 10 / 11 (x64).
- Android-устройство с включенной USB-отладкой.
- `adb`. Совместимая связка поставляется в папке `platform-tools/` рядом с приложением (скачайте [platform-tools](https://developer.android.com/tools/releases/platform-tools) и положите `adb.exe` туда) либо `adb` доступный в `PATH`.

## Требования Android

- Включите «Режим разработчика» (Звук/О программе → тап по номеру сборки 7 раз).
- Включите «Отладку по USB».
- При первом подключении подтвердите запрос разрешения на экране устройства.

## Структура проекта

```
src/adb_music_sync/
  __init__.py       # версия (single source of truth)
  __main__.py       # точка входа
  adb.py            # AdbClient — единственная точка вызова adb (subprocess)
  errors.py         # иерархия типизированных ошибок
  models.py         # Device, StorageTarget, TransferItem, AppState, ...
  storage.py        # определение внутренней памяти / SD-карт
  scanner.py        # рекурсивное сканирование локальной библиотеки
  paths.py          # валидация и безопасность путей назначения
  transfer.py       # движок передачи (очередь, .part, retry, state machine)
  controller.py     # контроллер GUI (worker-потоки)
  gui.py            # окно PySide6
  config.py         # атомарное сохранение настроек
tests/
  fake_adb.py       # FakeAdbClient (in-memory ADB)
  test_*.py         # unit + integration тесты
```

## Сборка

Рекомендуемая версия Python — **3.11** (совпадает с CI). Сборка на других версиях не проверяется.

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Скрипт создаёт standalone `.exe` (PyInstaller, onefile, windowed), затем запускает собранный `.exe` в режиме `--smoke-test` (импорт runtime-модулей + проверка загрузки PySide6, без GUI и без ADB), и только после успешного завершения собирает portable-архив `adb-music-sync-0.2.0-windows.zip`.

Для сборки используются штатные Qt-hooks PyInstaller без `--collect-all PySide6`: в EXE попадают используемые Qt-модули и их зависимости. Зависимость `PySide6-Essentials` предоставляет нужные QtCore/QtGui/QtWidgets без пакета Addons. Скрипт и CI показывают фактический размер EXE и отклоняют сборку больше 80 MiB. Frozen smoke test загружает графический платформенный плагин и создаёт виджеты/диалог выбора файла без показа окон и обращения к ADB.

В portable-сборке папка `platform-tools/` пуста — положите туда `adb.exe` (и сопутствующие файлы) из официального [Android platform-tools](https://developer.android.com/tools/releases/platform-tools), либо убедитесь, что `adb` есть в `PATH`.

## Известные ограничения MVP

- Сравнение файлов — по размеру (не по содержимому/checksum).
- Нет resume внутри одного файла: оборванный файл передаётся заново целиком.
- Пауза останавливает очередь между файлами (активный `adb push` не прерывается мгновенно); точный посекундный прогресс одного файла не гарантирован.
- Нет ADB over Wi-Fi, автообновлений, зеркальной синхронизации и удаления файлов (осознанно).
- Определение съёмных накопителей зависит от прошивки; на некоторых ROM список томов может отличаться.
- Shell-quoting (пути с `'`, `"`, `&`, `#`, `$`, backticks, Unicode) проверяется unit-тестами через единый POSIX-quoting helper; окончательная проверка на реальной Android shell зависит от конкретного устройства и прошивки.

## Troubleshooting / Diagnostics

Чтобы диагностировать проблемы с определением устройства или хранилищ на реальном Android-плеере (например, FiiO JM21), выполните следующие команды и приложите их вывод к баг-репорту:

```
adb devices -l
adb shell getprop ro.product.model
adb shell getprop ro.serialno
adb shell ls -la /storage
adb shell sm list-volumes
adb shell df -k /storage/emulated/0
```

Ключевые моменты:

- Устройство должно отображаться в `adb devices -l`. Некоторые плееры (FiiO) показывают host serial как `?`, но имеют рабочий `transport_id` — приложение обращается к ним через `adb -t <transport_id>`.
- SD-карта определяется по строке `public ... mounted <name>` из `adb shell sm list-volumes` (например `external_sd`), а не только по UUID-имени (`A12B-34CD`).
